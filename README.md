# 간호인력 통합관리 (시연용)

병원 간호국의 직원 상태(현원, 휴직, 퇴직, 입사예정)를 **기준일 하나로 일관되게 계산**하고, **왜 그 상태인지 근거**와 함께 보여주는 웹앱입니다.

> **이 저장소의 모든 직원 이름과 사번은 가명입니다.** 실제 직원과 관계가 없으며, 실제 인사정보는 들어 있지 않습니다. 이 앱에는 로그인과 권한 관리가 아직 없으므로 **실제 인사정보를 넣으면 안 됩니다.**

## 왜 만들었나

간호직 경력대장, 서무·기능직 경력대장, 직원현황배치표를 Excel 매크로로 따로 관리하면 같은 직원의 상태가 파일마다 어긋나거나, 매크로를 다시 돌릴 때 표시가 사라지는 문제가 생깁니다. 그래서 같은 사번과 같은 기준일로 같은 결과를 내는 하나의 웹앱을 만들고 있습니다. 기획서는 [PRD.md](PRD.md)에 있습니다.

## 지금 되는 것 (이번 사이클: 조회 전용)

- **직원 목록** (`/employees`): 기준일을 고르면 총원과 상태별 인원, 직원 표를 보여줍니다. 부서, 상태, "경고 있는 직원만"으로 거를 수 있습니다.
- **직원 상세** (`/employees/T00101`): 그 직원의 인사 기록을 날짜순으로 보여주고, 기준일의 상태를 정하는 데 쓰인 기록(근거), 기준일 이후라 적용하지 않은 기록, 확인이 필요한 기록을 표시합니다.
- **조회 API**: `GET /api/employees?asOf=YYYY-MM-DD`, `GET /api/employees/{사번}?asOf=YYYY-MM-DD`. 기준일이 없거나 형식이 틀리면 400, 없는 사번이면 404를 돌려줍니다.
- **상태 계산 규칙**: 입력 순서가 아니라 효력일 순서로 판정하고, 기준일보다 미래인 기록은 적용하지 않으며, 같은 날 기록이 겹치면 사람이 입력한 기록이 자동 생성된 기록보다 우선합니다. 판정이 애매한 기록은 임의로 고치지 않고 경고로 표시합니다. 자세한 규칙은 [DESIGN.md](DESIGN.md)에 있습니다.

아직 없는 것: 로그인·권한, 데이터 입력과 수정, Excel 가져오기·내보내기, 배치표 생성, 비교, 대시보드. 남은 문제는 [CHECK.md](CHECK.md)에 정리했습니다.

## 기술

Next.js 16(App Router), React 19, TypeScript, Tailwind CSS 4. 테스트는 Vitest입니다. 데이터베이스 없이 가명 시드 파일([data/seed-employees.json](data/seed-employees.json))을 읽습니다.

## 실행해 보기

Node.js가 필요합니다.

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:3000/employees`를 엽니다.

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm run build` | 배포용 빌드 |
| `npm run lint` | 코드 검사 |
| `npm run test` | 상태 계산, API, 화면 로직 테스트 |
| `npm run bench` | 가명 합성 1,500명 데이터로 목록 계산 속도 측정 |

## 폴더 구조

```
app/                  화면과 API (직원 목록, 직원 상세, 조회 API)
lib/hr/               상태 계산 엔진, 조회 처리, 날짜 유틸, 필터
data/                 가명 시드 데이터
tests/                테스트와 속도 측정
PRD.md PLAN.md DESIGN.md CHECK.md   기획, 작업 계획, 설계, 점검 결과
```

## 보안과 개인정보

- 비밀 값 파일(`.env`)과 `node_modules`는 저장소에 올리지 않습니다.
- 이 앱은 외부 서비스를 호출하지 않으며, 비밀 키를 읽지 않습니다.
- 실제 인사정보를 쓰려면 먼저 병원 개인정보·보안 담당자의 승인, 비식별화, 로그인과 권한 관리, 감사 기록이 필요합니다.
